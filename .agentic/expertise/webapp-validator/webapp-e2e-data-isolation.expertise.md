# Webapp E2E data isolation

## Mental Model

The webapp Playwright suite is designed to **never** run against the real `.agentrack/` folder (that's live dogfooding data for the whole repo). Isolation is achieved by pointing the E2E backend at a separate git worktree:

- E2E data lives under `validation/.e2edata/` (a git worktree), not `.agentrack/`.
- The backend is started with a `AGENTRACK_CWD` env var (set in `playwright.config.ts` webServer config) that overrides the tracker's working directory to the worktree.
- `e2e/setup.ts` (`ensureE2EWorktree()` / `resetWorktreeData()`) and `global-setup.ts` reset the worktree to empty defaults before each run.
- Playwright spawns its own backend with the correct env on every run; the `reuseExistingServer` flag is intentionally absent from the config (its default is `false`) and must NEVER be added — reusing a server risks hitting the real `.agentrack/` (see [webapp-server-ports.expertise.md](webapp-server-ports.expertise.md)).

**Hard invariant:** tests must NEVER hit the main `.agentrack/`. If testing issues/users appear in the real `.agentrack/`, the isolation override is not taking effect.

### Isolation hardening — LANDED and VALIDATED 2026-06-16 (issue `mqh3syrrnb`)

The recurring `UrlFilter*` seed leak (documented in the history section below) was fixed by a three-layer hardening. **All three layers were validated 2026-06-16 in session `mqh3syrrnb` and PASS.** The leak is no longer active; the real `.agentrack/` is clean (0 `e2e-seed` issues; the historical 50 leaked `UrlFilter*` seeds have been cleaned up). These layers are now the load-bearing isolation guarantees:

- **Layer A — CWD assertion in `global-setup.ts` (PASS, verified by negative test).** `server/utils/tracker.ts` exports `cwd = process.env.AGENTRACK_CWD || process.cwd()`; `/api/health` echoes it; `global-setup.ts` fetches `/api/health` and throws `E2E isolation guard FAILED` if `health.cwd !== getE2EDataDir()` BEFORE any seed is created. Verified fail-closed by booting a stale backend on port 5001 pointed at the real project root and invoking the real `globalSetup()` directly — it threw the guard error and aborted. Additionally, Playwright 1.60 itself fails closed (`http://localhost:5001 is already used`) when a stale server squats on the port, giving a second layer of protection.
- **Layer B — self-healing seeds (PASS on wiring/tagging; one non-blocking DEFECT, see below).** Every issue-creating spec (`phase2`, `phase3`, `dashboard-roots`, `url-filters`) wires `test.afterAll(() => cleanupE2ESeeds())`; `phase1`/`phase4` don't create tracker issues and correctly have no `afterAll`. EXHAUSTIVE grep confirmed 100% of seed-creation call sites tag issues with `e2e-seed` — zero untagged seeds. `cleanupE2ESeeds()` in `e2e/setup.ts` lists by tag and DELETEs each, tolerating already-deleted ids (404/non-OK swallowed). **Defect (non-blocking, tracked by idea `mqh5aew5am`):** the helper issues parallel `Promise.all` DELETEs against the backend's unlocked file store; concurrent DELETEs race and some are silently dropped — empirically 2 of 3 tagged seeds survived a single cleanup pass. A second pass cleans up, and `global-setup`'s `resetWorktreeData()` is the authoritative wipe, so no real-data leakage occurs. Suggested fix: serialize DELETEs (`for...of await`) or loop list-then-delete-until-empty.
- **Layer C — docs (PASS).** `packages/webapp/e2e/README.md` documents all five invariants: (1) backend resolves `AGENTRACK_CWD`, (2) health cwd assertion in global-setup, (3) port separation 5001/5000 vs 3001/3000, (4) never set `reuseExistingServer: true`, (5) worktree reset runs before every run. Plus a Self-healing seeds section.
- **Invariants verified:** `AGENTRACK_CWD` name unchanged across `playwright.config.ts` and `server/utils/tracker.ts`; `reuseExistingServer` absent from BOTH webServer entries; e2e ports 5001/5000 distinct from dev 3001/3000; `global-setup` still calls `ensureE2EWorktree()` + `resetWorktreeData()` before any test.

**Residual cosmetic bug (part of `mqh5aew5am`):** the Layer A guard error message in `global-setup.ts` contains a literal `${BACKEND_PORT}` (the second concatenated string uses `"..."` instead of a backtick template literal), so the port number isn't interpolated. The guard still fires correctly; the message is just confusing.

### Manual `agt` commands during validation

The isolation rule applies to **manual** testing too, not just the Playwright suite. When the validator needs to run `agt` commands by hand during validation work, run them from the **`validation/` directory**, never from the project root. The `validation/` directory has its own `.agentrack.json` pointer that resolves to the isolated `validation/.e2edata/` tracker, so commands there write to the test worktree and never pollute the real `.agentrack/`. Running `agt` from the repo root would operate on live dogfooding data. (Source of the `.agentrack.json` pointer claim: the agent's 2026-06-16 advisory answer — verify by reading `validation/.agentrack.json` if it ever seems wrong.)

The count of `UrlFilter*` issues in the real `.agentrack/` **grew from 50 to 51** between the first and third triage and new stamp batches keep arriving, so new seeds are still being emitted (the original batch was also never bulk-cleaned). Cleanup idea `mqh0su9kgq` remains unactioned as of the fifteenth triage — if `UrlFilter*` issues are still present on a future lookup, the cleanup has not run; do not treat them as real work.

**Source of the leak (confirmed):** the `seedIssues()` helper in `packages/webapp/e2e/url-filters-validation.spec.ts` (around lines 40–62) POSTs directly to `http://localhost:3001/api/issues` with `assignee: "webapp-validator"`, empty description, no tags, priority 3, and title `UrlFilter<Status>-${Date.now()}-${random}`. One `seedIssues()` call emits 5 sibling issues (one per status) sharing the same timestamp+random stamp (e.g. `uz574m`). When that POST hit a backend on port 3001 that was running **without** the `AGENTRACK_CWD` isolation override, the seeds were written into production data instead of the worktree.

**Leak vector now CONFIRMED (2026-06-16 advisory session).** The "exact trigger" gap is closed: the leading theory — a manually-started dev server squatting on port 3001 — was observed live. A shell-launched `bun run dev:server` (PID 88851) plus its `bun run dev:frontend` / vite siblings (PIDs 88850–88856) were found alive via `ps aux`, started WITHOUT `AGENTRACK_CWD`. That backend bound port 3001 to the real `.agentrack/`. When the Playwright suite runs while that server is squatting, the seed POSTs to `http://localhost:3001/api/issues` land in production data instead of the isolated worktree.

**Current config verified CLEAN (2026-06-16).** Grepping the live source confirmed: the env var is correctly spelled `AGENTRACK_CWD` everywhere (no `AGENTACK_CWD` typo), and `reuseExistingServer` is absent from `playwright.config.ts`. The earlier "suspected typo" escape hatch is now REFUTED for current code. So the pollution does **not** come from a broken Playwright config — it comes from a **runtime collision**: a manually-started (or leftover) dev server occupying the E2E port without the override.

**Two guards that let it recur (both NOW LANDED — were missing at the time of the leak):**
1. **`global-setup.ts` did NOT assert the backend's resolved CWD.** It reset the worktree but never verified the server it POSTs to was actually using `validation/.e2edata/`. So if a non-isolated server grabbed port 3001, Playwright proceeded silently against real data. **FIXED (Layer A above):** global-setup now asserts `health.cwd` before any seed creation. Verified fail-closed.
2. **Seed issues had no `afterEach` cleanup and no identifying tag.** Leaked seeds accumulated forever; there was no self-healing path. **FIXED (Layer B above):** seeds now carry the `e2e-seed` tag and every seed-creating spec runs `cleanupE2ESeeds()` in `afterAll`. (Residual: the parallel-DELETE race in `mqh5aew5am` weakens but does not break the self-healing guarantee.)

**Pre-flight check before running any Playwright E2E (do this every time):** confirm no stray dev server is squatting on 3001, and prefer `ps aux | grep -E "bun run dev|vite"` over `lsof` (in this sandbox `lsof -iTCP:3001` returned empty even while the leftover servers were alive — `ps` is the reliable signal). Kill leftovers (`pkill -f "bun run dev:server"; pkill -f "vite.*5174"`) before invoking `npx playwright test`.

**Resolution actions taken in that session:**
- Commented evidence on `mqh0lg9d2i`, reassigned to `project-manager` (status left `todo` — nothing to implement).
- Created idea **`mqh0su9kgq`** "Clean up 50 leaked UrlFilter E2E seed issues and harden isolation to prevent recurrence" (priority 2) with two work items: bulk cleanup of the 50 issues, and a root-cause guard. Suggested guards: (a) a `global-setup` assertion that the running backend resolves `AGENTRACK_CWD` to the e2e data dir (e.g. GET a config/health endpoint that echoes cwd) and fails the run otherwise; (b) have `seedIssues` tag issues (e.g. `e2e-seed`) with an `afterEach` cleanup so leaked seeds are self-healing; (c) README note that nothing should bind port 3001 manually while tests run.

**Identifying leaked seed issues (reusable heuristic):** title matches `^UrlFilter(Idea|Todo|InProgress|Done|Closed)-`, no parent, empty description, no tags, priority 3, assignee `webapp-validator`.

### How the override can silently break

If the env-var override doesn't apply, the backend falls back to its default working directory (`.agentrack/`), and every test run writes into real production data. Candidate vectors:

1. **A manually-started dev server on port 3001 without the env var — CONFIRMED 2026-06-16.** The E2E suite POSTs seeds to port 3001 directly; if a non-isolated server is listening there, seeds land in real data. Observed live (PID 88851 `bun run dev:server` without `AGENTRACK_CWD`). **This is the active leak vector.**
2. **Adding `reuseExistingServer: true`** to the config, which would let Playwright grab a backend that was started manually without the env var. The flag is intentionally absent from `playwright.config.ts` (Playwright's default is `false`); it must never be added.
3. **Env-var name typo (`AGENTACK_CWD` vs `AGENTRACK_CWD`) — REFUTED for current code (2026-06-16 grep).** Originally flagged as suspected; the live source confirms the spelling is consistent everywhere. Listed here for history; do not re-investigate unless the grep finding is overturned.
